# ECO 合炉（测试版）

## 入口

统一入口为「采购管理 → ECO合炉」，位于「汰换记录与统计」右侧。

- 列表展示已入库、当前库存精确匹配、冷却结束且未汰换的采购配方。
- 默认显示“未上合炉”；可切换“已上合炉 / 已提交”和“全部配方”，每个分类显示配方数量。卡片同时显示原批次中的配方编号。
- 创建前保存待确认记录，成功提交后自动归入“已上合炉 / 已提交”；平台是否正式发布仍需查询确认。网络超时等不确定结果保留待确认标记，不能直接重复创建；明确失败则回到未上合炉。
- 已有旧炉可手动“标记已上合炉”，核实失败或取消后可“标记未上合炉”。手动操作只改变本地分类，不创建或取消平台合炉。官方列表接口不提供完整材料资产清单，不能仅凭同名标题自动关联旧炉。
- 「我的合炉」查询后按精确绑定炉号同步本地状态：平台拼炉中、当前用户为炉主、正在匹配且明确不显示支付按钮，或进入汰换、公示、客服介入、竞价、完成阶段且未要求支付时，更新为「已上合炉」。仅 `CanPayment=false` 不足以认定确认，失败、缺失或查询未包含的炉子不自动修改。平台确认不会被后续本地「已提交」进度覆盖；关闭窗口后采购列表更新，无定时轮询。
- 标记绑定具体 Steam 账号和材料资产；修改账号或更换材料后不沿用旧标记。已提交配方即使材料暂时不在库存，也保留在对应分类中，按钮变为“查看合炉”。
- 配方按采购日期分组，日期支持展开和收拢；每炉显示当天编号、账号名、成本和材料明细，不再显示旧采购批次名称或账号 ID。支持按账号和饰品名筛选。
- 在此页面点击「API 设置」配置授权，点击「图文指引」查看四页操作示意。
- 在配方卡片点击「发布合炉」，点击页面「我的合炉」查询。小助手不提供押金支付入口，请自行进入ECO APP缴纳押金。
- 计算结果、配方管理及采购材料明细不再单独提供发布入口。

## 首次配置

1. 在 ECO App 申请开放能力，审核后页面里的「身份 ID」就是小助手的 PartnerId。
2. 打开本页「API 设置」，选择「个人模式」，粘贴身份 ID。
3. 点击「生成 RSA 密钥」，私钥会自动填入并留在本机；已经有配对私钥时可选择导入。
4. 点击「复制公钥」，在 ECO 开放平台开启「签名验证」，进入 RSA公钥设置，粘贴对应公钥并保存。
5. 在小助手保存 API 设置，再到「我的合炉」查询列表验证密钥与权限。Timestamp 和 Sign 由程序生成，无需手填。
6. 个人模式不需要 ServiceProviderId 或 OpenID，这两个字段仅在服务商模式显示。当前程序通过查询获取结果，不需要设置接收回调通知。
7. 截图中的购买、出租、出售开关是 ECO 业务权限，不是小助手要填写的密钥。公开文档未明确合炉接口和这些开关的一一对应关系；若返回 6003（接口无权限访问），需向 ECO 确认合炉创建、查询和支付权限，不能仅凭 API 申请通过判断全部业务权限已开通。

ECO 官方设置页在关闭签名验证时隐藏 RSA公钥设置。小助手当前按官方 RSA 签名协议接入，不使用仅身份 ID 的无签名模式。

私钥在 Windows 上通过 DPAPI 加密保存在应用设置中，不会发送给 ECO；请求只发送身份信息、时间戳和签名。

## 单页发布与套用已有合炉

- 发布窗口不再分三步。点击「刷新 / 读取参考价值」，在「套用已有合炉」选择对应的炉子，即显示该炉的 `AllMatRefPrice`，不需要重新创建。
- 账号只显示名称，新合炉标题默认「正期望MK」。创建成功后，通过创建前后的炉号识别并自动套用新炉；平台列表尚未更新时保留已创建状态，刷新即可继续，不重复创建。
- 已有合炉选项显示标题、参考价值、已添加材料数，当前绑定的炉子标注「当前配方」，完整炉号放在提示中。
- 材料总参考价值、收料成本和上架总售价分别显示；收料成本取采购记录中的实际材料价格，不随上架加价变化。
- 配方材料、售价、批量加价和私密上架操作都保留在同一页。已有合炉可从配方卡片「查看合炉」继续处理。
- 私密上架通过官方 `PublishStock`（`IsSecret: true`）提交精确资产及库存 ID；逐件处理结果，已成功的材料不会重复提交，结果不确定时先核对平台。
- 配方材料全部私密上架成功后，自动切到「我的合炉」并刷新、选中当前合炉；部分失败或结果待确认时保留发布页。
- 私密上架不等于材料已加入合炉。已添加材料和是否可支付以 ECO 返回为准，平台未关联时到 ECO 完成添加；请自行进入ECO APP缴纳押金。

开发验证使用模拟响应，不在真实账号创建、上架或支付。

建炉请求包含材料及初始价格，平台可能同时完成私密上架。第二步遇到已私密上架的精确资产时，使用 `GetSellGoodsList` 匹配自己的 `GoodsNum`，通过 `GoodsPublishedBatchEdit` 更新售价，不重复上架；提交后重新读取私密在售列表，只有实际价格与目标一致才标记完成。未匹配到私密记录的不可上架材料不会自动下架或改为公开出售。待核对的目标售价随配方记录保存。

## 参考价值与炉主售价

- 发布窗口与「我的合炉」统一只使用 ECO 合炉列表的 `AllMatRefPrice`，不再展示库存市场价列、合计或读取按钮。创建前显示「材料总参考价值：创建后查询」。
- 「我的合炉」列表新增「材料总参考价值」，只展示 ECO 返回的 `AllMatRefPrice`，没有返回时标注「未返回」。创建前尚无该炉的正式参考值，不使用库存市场价或售价冒充。
- 「炉主上架材料总售价」合计当前各行的可编辑售价，用户修改后实时更新。读取参考价不会覆盖已经填写的售价。
- 在「每件售价增加」填入 N 元，点击「一键增加」，每件当前售价增加 N 元。十件材料的总售价增加 10N 元；重复点击会继续累加，材料总参考价值不随本地售价修改。若任一材料将超出售价上限，本次全部不修改。
- 发布表按实际 5 / 10 件材料设置高度，十件材料可一次看全。

## 按当前市场价格定价

- 发布页点击「读取 ECO 同磨损区间价格」，通过官方 `/Api/Market/SellGoodsList` 的 `HashName`、`StartPaintWear`、`EndPaintWear` 查询。区间沿用材料采集分档，取返回挂单中符合区间的最低 `SellingPrice`；它是当前在售价参考，不是精确磨损的成交估值。
- 初始售价不再用收料成本填充。报价缺失保留 0，不以成本补齐；原有合炉已保存的目标售价仍保留。
- 以本节取代上文固定金额「每件售价增加」规则：110% 表示每件区间参考价乘 1.10，四舍五入到分；重复应用不叠加。收料成本、市场报价和合炉 `AllMatRefPrice` 分别展示。
- 读取价格与应用比例不会创建合炉或实际改价，仍需明确确认创建或上架。
